# LINK PREVIEW UNIFIED V1

最后更新：2026-06-07

## 1. 目标

把创建详情页中的 `粘贴商品链接` 统一成一个稳定入口：

- 前端只有一个交互能力：`粘贴商品链接`
- 后端只有一个统一接口：`POST /api/v1/material/link-preview`
- 不同来源站点走不同适配器，但返回结构保持一致

V1 的重点不是一次性覆盖所有电商平台的完整字段，而是：

1. 先稳定识别平台与规范化链接
2. 尽可能返回商品名称 / 类目 / 品牌
3. 当目标页存在登录门槛或反爬限制时，明确告诉用户当前拿到了什么、还缺什么

## 2. 统一返回结构

当前统一返回 `ProductLinkPreviewDTO` / `ProductLinkPreview`：

- `originalUrl`
- `resolvedUrl`
- `host`
- `platform`
- `productName`
- `category`
- `rawCategoryPath`
- `brandName`
- `pageTitle`
- `httpStatus`
- `fetched`
- `loginRequired`
- `source`
- `message`

前端只消费这一个结构，不感知底层是独立站解析还是国内电商适配器。

## 3. 当前适配器分层

### 3.1 独立站 / 普通网站

当前实现：`WebsiteMetadataProductLinkPreviewSource`

能力：

- 读取页面标题
- 读取 `og:title` / `twitter:title`
- 解析 JSON-LD Product
- 解析 BreadcrumbList
- 推导品牌、类目、类目路径

适用：

- 品牌站
- 独立站
- 公开可访问商品页

### 3.2 国内电商

当前实现：`DomesticEcommerceProductLinkPreviewSource`

V1 能力：

- 识别平台
- 规范化长链接，移除常见 tracking query
- 在平台页直连可用时尽量读取标题 / 类目 / 品牌
- 在登录门槛页上保留平台与规范化链接，并明确提示手动补充

V1 真实结论：

- 服务端直连淘宝类页面时，经常只能拿到登录跳转页或不完整 HTML
- 因此“国内电商自动补齐全部字段”不能只依赖 Spring Boot 直连

## 4. 已完成的真实验证

### 4.1 独立站验证

已在创建页浏览器流程中验证：

- Samsung 商品链接可回填：
  - 商品名称
  - 商品类目
  - 品牌名称
  - 平台

### 4.2 淘宝长链接验证

已验证超长淘宝链接当前行为：

- 自动识别 `平台 = 淘宝 / 天猫`
- 自动清理 tracking 参数并保留核心 `id` / `skuId`
- 如果页面只返回登录壳，则给出清晰提示，不再表现为接口崩溃

### 4.3 登录态淘宝页验证（无店透视）

已通过登录态 Chrome 真实页面验证：

- 不依赖 `店透视`
- 仅通过原生页面标题 / 页面内嵌状态，也能拿到：
  - 商品名称
  - 店铺名
  - 类目路径：`住宅家具>几类>茶几`
  - 品牌：`#0 工厂`
  - 型号：`MY-A08`

这说明：

- 国内电商最小字段抓取可以不绑定店透视
- 但需要“登录态浏览器执行”这条能力

### 4.4 登录态淘宝页验证（店透视）

已确认店透视在真实淘宝页中注入并能显示：

- 类目
- 店铺
- 销量 / 销售额 / 评价等增强信息

因此店透视适合作为：

- 国内电商浏览器适配器的增强层
- 或原生提取失败时的 fallback

## 5. 当前推荐架构

V1 统一架构如下：

1. 前端统一调用 `POST /api/v1/material/link-preview`
2. 后端做 URL 规范化与安全校验
3. 根据 URL 来源分配适配器：
   - 独立站：`website-metadata`
   - 国内电商：`domestic-ecommerce`
4. 对国内电商，下一阶段优先接入浏览器 worker：
   - 先读原生登录态页面
   - 再用店透视做增强 / fallback

## 6. 当前边界

V1 还没有完成的部分：

- 还没有把“登录态浏览器 worker”正式接回 `/api/v1/material/link-preview`
- 国内电商适配器当前仍以服务端可直连内容为主
- 店透视验证已经完成，但还没有正式成为生产链里的可调用数据源

## 7. 当前用户体验要求

创建页应保持这些原则：

- 不把失败表现成崩溃
- 能识别的平台先识别
- 能清理的链接先清理
- 能自动带的字段先自动带
- 拿不到的字段明确提示用户手填

当前页面已配合显示：

- 解析来源
- 平台
- 商品名称
- 商品类目
- 类目路径
- 品牌名称
- 登录门槛提示

## 8. 下一步

最推荐的下一阶段动作：

1. 增加 `domestic-ecommerce-worker` 协议
2. 让后端对国内电商优先请求浏览器侧 worker
3. worker 内部按这个优先级取数：
   - 原生登录态页面提取
   - 店透视增强 / fallback
   - 部分结果 + 明确提示
4. 继续保持前端接口和返回结构不变

这样可以把国内电商能力接进来，而不破坏当前已经跑通的独立站链路。
